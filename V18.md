# V18.md — Spécification officielle de NURU V18 (CONTRAT D'ARCHITECTURE)

> **Statut** : document vivant — chaque décision validée par le débat contradictoire
> y est inscrite et devient ENGAGÉE.
> **Règle absolue** : une fois inscrit dans V18.md, un point :
> - est considéré comme validé ;
> - ne peut plus être ignoré ;
> - doit être implémenté exactement comme spécifié ;
> - ne peut être sauté sans justification explicite et nouvelle décision d'architecture.
>
> **Traçabilité exigée** pour chaque décision :
> rapport d'expert → débat contradictoire → entrée V18.md → commit d'implémentation.

## Processus (rappel)

1. **Revue technique** : l'assistant analyse chaque rapport d'audit (mode analyse UNIQUEMENT —
   zéro modification de code, zéro patch, zéro implémentation).
2. **Document d'analyse** par rapport : résumé des recommandations → vérification dans le code →
   analyse critique (verdict ✅/⚠/❌) → contre-arguments → questions pour l'expert → décision proposée.
3. **Débat contradictoire** : les remarques de l'assistant sont renvoyées à l'auteur du rapport ;
   l'expert répond ; l'assistant répond ; itérer jusqu'à solution techniquement solide.
4. **Inscription dans V18.md** : chaque décision validée est ajoutée ci-dessous avec sa traçabilité.
5. **Implémentation** : relire V18.md entièrement → transformer chaque point en tâches → checklist
   → cocher uniquement quand réellement implémenté → vérifier dans le code → jamais passer à la
   tâche suivante tant que la précédente n'est pas terminée.
