## 1.2 Analyse fonctionnelle

### Ce que fait NURU

Assistant IA personnel local-first pour Apple Silicon, basé sur MLX (Phi-4-mini 4-bit + fallback Qwen2.5-1.5B), avec fallback Cloud (Groq llama-3.3-70b-versatile primaire, OpenRouter > DeepSeek en repli) et RAG sur documents utilisateur indexés.

### Capacités actuelles

- Chat multi-intent (RAG / WEB / COMPLEX / SIMPLE / GENERAL)
- RAG hybride : vectoriel (sqlite-vec e5-base-768d) + BM25 (FTS5) + cross-encoder reranker + HyDE + Spotlight (mdfind macOS) + décomposition de requête
- Mémoire court terme (in-memory session window=5) et long terme structurée (faits utilisateur)
- Pipeline agentique (planner/executor/verifier/recovery) **mais non branché**
- Génération de documents réels (Word/PDF/PPTX/XLSX/MD) via DocumentGenerator (V9 fix)
- Watchdog temps réel sur Documents/Desktop/Downloads
- Dashboard PySide6 15 pages : chat, documents, sessions, memory, diagnostics, logs, stats, settings, guides, tool_tester, v6_system, console, agent_status, feedback_bar, memory_explorer
- TTS Piper / STT faster-whisper
- Cache LLM L1 (RAM MD5) + L2 (SQLite cosine ≥0.92)
- TraceCollector + SelfEval + Optimizer (learning loop théorique)

### Architecture RAG — état réel

```python
RAGEngine.retrieve(query)
  ├── réécriture CloudQueryRewriter (CloudLLM sync)
  ├── embedder.embed(query)                 # MLX e5-base, dim 768
  ├── sqlite-vec MATCH cosinus ORDER distance LIMIT 15
  ├── _should_use_reranker(top1_score)      # RAM >1.5 Go et score >0.15
  ├── CrossEncoderReranker (si activé)
  ├── MultiSearchOrchestrator (V8+)         # vector + fts + hyde + spotlight
  ├── SpotlightSearch (mdfind macOS)        # lit contenu réel
  └── sandbox context → injection prompt avec sanitization
```

### Système de mémoire — état réel

- **memory_store.py** : SQLite in-memory + persistance, session_window=5
- **memory/schema.py + episodic/semantic/user/errors/manager** : V9 architecture propre
- **long_term_memory.py + memory_bridge.py** : extraction post-session via LLM
- **memory_bridge** : connecte V5 (memory_store) et V9 (memory/*.py)
- **Problème :** deux bases parallèles (`memory_v9.db` vs `nuru.db`) ; memory_bridge tente de fusionner sans garantie

### Système agentique — état réel

`src/agent/` contient un Planner (rules-based, sans LLM), Executor (avec MOCK_TOOLS par défaut), Verifier (heuristique), Recovery (4 actions), Resume (persistance JSON), Orchestrator (loop séquentiel). **MAIS** : ce pipeline n'est appelé par **aucun** point du runtime principal. `nuru_core.process_query` → `core/orchestrator.process_query` → ne touche jamais `src/agent/`. → **Code mort pour le runtime**.

### Système de routage — état réel

`SemanticRouter.route()` (src/semantic_router.py) implémente 8 passes :
1. Trivial (regex Greetings, identité)
2. Patterns documentaires (mots-clés CV/rapport/projet)
3. Connaissance générale (maths, logique)
4. Patterns web (actualité, prix, météo)
5. LLM classification (~100ms, cloud — utilisé seulement en cas ambigu)
6. Spotlight (SpotlightSearch.search)
7. Cloud fallback (si RAM trop basse)
8. Clarification (si score < seuil)

`core/router.py` ajoute PolicyEngine + hybrid_strategy + ascend Cloud if RAM low.

### Système de recherche documentaire

- **RAG** : sqlite-vec 768d + BM25 FTS5 + reranker + multi-stratégie (+HyDE)
- **Spotlight** : mdfind macOS + lecture contenu (court-circuit si >500 chars trouvés)
- **DocumentWatcher** : watchdog sur Documents/Desktop/Downloads
- **DocumentExtractor** : extraction LLM (Cloud) → `doc_structured` table

### Système de gestion des outils

`src/tools/document.py` : DocumentGenerator (Word/PDF/PPTX/XLSX/MD) — pipeline propre avec validation de spec.
`src/tools/registry.py` : ToolRegistry minimal.
**Problème :** utilisé nulle part dans le runtime actif (l'UI tool_tester existe mais ne fait qu'afficher le catalogue).

### Interface utilisateur

Dashboard PySide6 + qasync : chat avec streaming, telemetry live (tok/s, RAM, cache hits), 15 pages. **Points faibles :**
- `dashboard.py` 1286 LOC, mélange UI + business + télémétrie
- `settings_page.py` 1392 LOC (dieu-objet), formulaire monolithique
- User a noté : "le dashboard met en cache les modules .pyc — redémarrage nécessaire après modification du code source" (memory)
- Pages Memory : "toutes les pages doivent montrer du contenu réel" (memory)

### Système de configuration

`src/config.py` (singleton mutable) :
- hérite de pydantic-settings.BaseSettings
- lit env NURU_* + .env
- `load_yaml()` applique `config/settings.yaml` via setattr (silencieux)
- clés API via `keyring.get_password("com.nuru.assistant", ...)`
- helpers : set_module_enabled, _save_yaml_key

**Problèmes :** config double-source (YAML + env) avec application silencieuse, defaults divergent des valeurs YAML (ex: rag_max_context_tokens 1500 dans code, 2000 dans YAML).

# PHASE 4 — AUDIT IA

## 4.1 LLM & Routage

- **Fenêtre :** max_prompt_tokens=8192 (V10.2, +reserved 2048) → 16384 total pour Phi-4-mini
- **Sampling :** temperature=0.7 (Cloud defaut), repetition_penalty via MLX
- **Routage :** 8 passes (semantic_router.py:6-12) ; LLM classification en backup
- **Prompt engineering :** excellent — `SYSTEM_PROMPT_STATIC` très détaillé, intention-aware (`build_system_prompt`)
- **SystemPrompt** : pas de `{query}` interpolation directe dans SYSTEM — OK. Mais le user/assistant conversationnel passe en clair dans full_prompt.

## 4.2 Agentique

- **Planner :** rules-based (mots-clés), pas de LLM. Limite : plans figés.
- **Executor :** MOCK_TOOLS par défaut, ToolRegistry.vide.
- **Verifier :** heuristique simple (regex, count).
- **Recovery :** 4 actions (RETRY / SKIP / ESCALATE / ABORT).
- **Resume :** persistance JSON.
- **Boucle réflexion :** absente (pas de self-critique au niveau LLM).
- **Multi-agent :** AUCUN. Tout le système est mono-agent.

**Verdict :** Pipeline agentique riche en théorie, **zéro valeur opérationnelle** parce que pas câblé.

## 4.3 Mémoire

- **Court terme :** session_window=5, MemoryStore in-memory + SQLite persistance ✓
- **Long terme :** LongTermMemory + MemoryBridge ↔ V5+V9 (architecture complexe)
- **Persistance :** double (nuru.db + memory_v9.db)
- **Rappel :** cosine ≥0.92 sur cache L2 ; sinon vector retrieval classique
- **Hallucinations :** ResponseGuard strict mode refuse sans contexte. EvidenceVerifier et FactChecker en post-gen.

**Risques :** MemoryBridge.py:84 : except:pass — pont HS silencieusement possible.

## 4.4 RAG — Pourquoi des informations ne sont jamais utilisées

| Cause | Effet |
|-------|-------|
| `rag_score_threshold = 0.30` (settings.yaml) vs `rag_min_usable_score = 0.20` (config.py) — divergence | Chunks entre 0.20-0.30 peuvent être soit inclus soit vidés |
| `RAGQualityGate` (orchestrator.py:280-300) : si pas de mot-clé commun → vide contexte | Mauvaise paraphrase = drop légitime |
| RAG exécuté UNE seule fois (audit fix) mais decompose uniquement si `should_decompose` | Cas multi-facette perdu |
| Spotlight bypass force LOCAL_ONLY (router.py:69) | Si Spotlight faux positif, on rate Cloud |
| Embedder e5 multilingual : sous-optimal sur texte technique français-agronomique | Similarité cosinus basse → drop |
| Chunking (rag/v2_chunking.py) : défaut 2000 chars sans overlap paramétrable | Perte aux frontières |
